## What's covered

<CardGroup cols={1}>
  <Card title="API keys & tokens" icon="key">
    AWS access/secret keys, GCP API keys, GitHub tokens, Stripe secret/publishable keys, Azure subscription keys, and PEM-format private keys. Guardian filters out obvious placeholder values (like example keys in documentation) using an entropy check, so it's less likely to false-positive on a made-up sample key than a plain pattern match would be.
  </Card>
  <Card title="Bare .env content" icon="file-lock">
    A message or file containing raw `KEY=VALUE` secret assignments, a path referencing a `.env` file, or the contents of an actual `.env`/config file.
  </Card>
  <Card title="Leaked .env inside a ZIP" icon="file-zipper">
    A `.env` or similarly named secret file found by filename inside an uploaded ZIP archive — root-level is treated as more severe than nested.
  </Card>
</CardGroup>

## Example (masked)

```text
Detected: aws_access_key
Masked value shown to you: AKIA****EXAMPLE
Severity: critical → BLOCK
```

The full key is never shown back to you or stored anywhere — see [Privacy & Trust](/privacy-trust).

## Where this applies

- Chat messages — via [scan_prompt](/how-scanning-works/scanning-messages)
- Uploaded `.env`/config files and ZIP archives — via [scan_document](/how-scanning-works/scanning-files)

See [Severity Levels](/results/severity) for exactly how each finding maps to ALLOW/WARN_CONFIRM/BLOCK.
